# Paper 1 production job lists

The eleven lists under `data/joblists/paper1/` (plus `day1_null_grid_n20.json`, the Deviation 50 day-1 combination of two of them, section 2) implement the hardware stage of the Paper 1 pre-registration
(`preregistration_q1`, **v0.13.1**, 20 Sep 2026, with Deviations 52–53 as adopted in the thread on 20 Sep): Section 2 (design), Section 3b (reset dial), Section 5 (Gate 2),
Section 6 (minute budget) and Deviations 17, 18, 22, 26, 27, 28–30, 33–53. They are generated by
`scripts/make_paper1_joblists.py`, budgeted with `gradvar.hardware.estimate_budget` (**model v3, Deviation 47**), packed
under the **Deviation 48** rule (one pub per dial mask carrying the draws as parameter rows), dry-run on FakeNighthawk, and
tested in `tests/test_paper1_joblists.py` (the committed files must equal the generator's output). Every list carries
`dry_run: true` and `preflight_review: "TBD: pre-flight review permalink"`; nothing submits until a pre-flight review is
posted and both fields change in the same commit (`data/joblists/README.md`, Flow).

```
python scripts/make_paper1_joblists.py                      # from data/calibrations/ibm_phoenix_2026-09-20T141736Z.csv (the newest committed calibration data, Deviation 53 (b))
python scripts/make_paper1_joblists.py --snapshot data/calibrations/ibm_phoenix_<run-day>.csv   # run-day regeneration (Deviation 46)
python scripts/make_paper1_joblists.py --check              # committed lists == generator output
python scripts/make_paper1_joblists.py --day1               # only day1_null_grid_n20.json (Deviation 50 day 1: null_controls + grid_n20 in one list)
python scripts/make_paper1_joblists.py --m-rule dev17 --out /tmp/p1_dev17   # Deviation 17 M for the budget comparison
python -m gradvar.hardware --joblist data/joblists/paper1/grid_n20.json      # dry run (fake backend)
python -m gradvar.hardware --joblist data/joblists/paper1/dial_arm.json --dry-run-sample 8   # sampled dry run of the dial lists
```

## 2. Contents

Conventions: k is the 1-based layer of the differentiated Ry, on the first qubit of the observable edge (Section 2, Gradient);
draw d of a point uses seed + d; seeds are deterministic blocks of 1000 per (rung, role, depth, k) from `SEED_BASE = 20261001`
(`make_paper1_joblists.seed_for`), so no two points share a draw unless by design: resilience 0 and 1 of one point share their
draws (paired H4 ratio), the four k of one sweep depth share theirs (paired layer-index ratio), the dial probes with the same
seed are paired draw by draw and mask by mask (Section 3b, Pairing). 4096 shots per shifted circuit; 16384 for the n100 L = 8
headline points and the Gate 1b references. **Job packing (Deviation 48)**: a grid or null-control point is one pub per draw
(the shifted pair, a (2, nL) bindings array); a dial probe is one pub per mask carrying its M draws as parameter rows (a
(M, 2, nL) array of shifted pairs, or (M, n l) rows of theta for the unshifted truncation circuits), so both shifts of a draw
share the mask (Deviation 38) and a gradient point is 256 pubs instead of 51,200 one-row circuits; a reference is one pub of
350 pairs. Every job holds at most 300 pubs (`max_experiments`, a pub counting once whatever its rows) and at most 12 MB of
bound parameter values (`gradvar.hardware.MAX_JOB_PARAM_MB`, a runner cap under IBM's request-size limit), consecutive pubs of
a group packed together (`data/joblists/README.md`, job packing). Masks come from `mask_lottery` (Bernoulli(`mask_p`) on the
SeedSequence (`seed + 1 + m`, `MASK_STREAM`), so a mask is never a function of a draw's angles) and are shared by all draws
of a point (see section 7, item 13).

## 6. Runner changes made for these lists (`gradvar/hardware.py`, merged with main's runner)

- **Deviation 48 packing** (`build_probes`, `_probe_pubs`, `budget_jobs`, `job_groups`): a `reset_dial` probe is one pub per
  mask carrying its M draws as parameter rows ((M, 2, nL) shifted pairs; (M, n l) θ rows when `unshifted`); M = 1 keeps the
  (2, nL) pair of the smoke-test lists. Both shifts of a draw share the mask (Deviation 38) and all draws share the K masks.
  `BuiltProbe.draws`, `theta_seeds`; `job.json` records `draws`, `theta_seeds` and per-draw `param_hashes`, and omits
  `param_values` above `PARAM_VALUES_INLINE_MAX` (4096 floats; the values are reproducible from the seeds). One CSV row per
  draw (`seed + d`, its hash). `mask_lottery`: Bernoulli(`mask_p`) on the SeedSequence (`seed + 1 + m`, `MASK_STREAM`), so
  a mask is never a deterministic function of draw m + 1's angles (with `default_rng(seed + 1 + m)` for masks and
  `default_rng(seed + d)` for θ it would be); `mask_seed` stays `seed + 1 + m`. List 02's bundles keep their own hashes.
